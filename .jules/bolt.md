## 2024-10-24 - N+1 Query Anti-Pattern in Firebase Fetching Loops
**Learning:** Found a critical N+1 query bottleneck in `BudgetService.getBudgetStatus` where `transactionService.getUserTransactions(userId)` was being called inside a `Promise.all(budgets.map(...))` loop. This meant the database was queried repeatedly for the identical set of transactions for every budget the user had. This is a common performance anti-pattern when calculating aggregate data based on related entities in a loop.
**Action:** When calculating statuses or aggregations that loop over multiple entities (like budgets, goals, etc.), always look for data fetches inside the loop. If the query parameters (like `userId`) don't change per iteration, hoist the data fetching outside the loop and reuse the retrieved dataset (e.g., `allTransactions`) for filtering inside the loop.
